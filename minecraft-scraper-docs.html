The backstory

Built by a Minecraft creator, for Minecraft creators

This workflow was built while actively running a Minecraft Shorts channel. The problem: finding content inspiration was a daily manual grind - searching YouTube, comparing view counts, trying to reverse-engineer why certain videos exploded. This tool automates that entire research process.

🎮
Creator-first design
The AI prompt is specifically constrained to solo creator production - no scripts requiring other players, only Mobs, Armor Stands, and Mods. This reflects real-world content creation constraints and makes the output actually usable.

YouTube Shorts search
Queries the YouTube Data API v3 for "Minecraft #shorts" filtered to the past 7 days, sorted by view count, pulling up to 500 results across 10 paginated pages. Only short-duration videos are returned.

Split & enrich each video
Results are split into individual items. For each video, two parallel API calls fetch detailed data: one for the video's own stats (view count, title, likes), and another for the channel's subscriber count. Both streams are then merged back together.
Video Stats API Channel Stats API Merge Node

Remove Duplicates Node

The viral filter - how breakout videos are detected

⚡ Both conditions must be true to pass

📉
Condition 1 - Small channel only
The channel must have 10,000 subscribers or fewer. This filters out established creators and surfaces only small channels - the ones that can teach you how to beat the algorithm without a built-in audience.

channel.subscriberCount ≤ 10,000
🚀
Condition 2 - Views massively outpaced subscribers
The video's view count must be more than 5× the channel's total subscriber count. A channel with 1,000 subscribers getting 10,000 views is a breakout. This ratio is the core signal.

video.viewCount > channel.subscriberCount × 5

This filter is the heart of the workflow. It doesn't just find popular videos - it finds disproportionately popular videos from small creators, which are far more instructive for growth than videos from channels that are already famous.

AI prompt design - creator constraints
🚫 Hard constraint
Solo creator mode
The AI is explicitly told: no scripts requiring other human players or actors. If the original video involved a prank or multiplayer concept, the AI must adapt it to work with Mobs (Villagers, Zombies), Armor Stands, or Mods.
🌍 Language handling
Non-English titles
The AI translates foreign-language video titles internally for context analysis, then writes all output in English. Minecraft is a global platform - this ensures no viral video is missed due to language.
🎯 Tracking ID system
ID matching architecture
Each video is assigned a tracking ID (its URL) before being sent to the AI. The AI must echo this ID back in its JSON output. This allows the merge node to correctly reunite scripts with their source videos even under parallel processing.
🎬 Script structure
50-second Short format
Every script is structured as: Visual Hook → Story/Action → Loop (a closing line that connects back to the opening). The loop design is intentional - it increases rewatch rate, a key signal in YouTube's Short algorithm.
AI output - what gets generated per video
1
Small Channel Hook Analysis
Explains exactly how this video grabbed attention without a large audience - identifying the specific visual, emotional, or narrative trigger that made it shareable from zero.
2
Full 50-second script
A complete, filmable script adapted from the viral concept with a unique twist. Includes production notes calling out any Mods or specific Mob AI behaviors needed to execute the concept solo.
3
Loop-back ending
A closing sentence designed to connect back to the opening of the video, encouraging viewers to rewatch - boosting the completion and loop metrics YouTube's algorithm rewards.

3-tier JSON parser - robust AI output handling

AI models don't always return clean JSON. The cleanup code node uses three layers of fallback to ensure no script is lost:

Tier 1
Standard JSON.parse
Strips markdown code fences, escapes control characters, extracts the JSON object between the first { and last }, then parses normally.
Tier 2
Regex extraction
If standard parsing fails, regex patterns individually extract the matching_id and script_content fields directly from the raw text string.
Tier 3
Graceful failure
If both methods fail, the record is flagged with FATAL_ERROR and the error message is captured - no silent failures, no lost data.
