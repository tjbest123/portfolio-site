Problem it solves

Traditional web hosting is slow, fragile, and unscalable

Hosting a website on a single server (like an EC2 instance or a traditional shared host) creates a single point of failure. If that server goes down, the website goes down. Furthermore, users on the other side of the world experience significant latency because data has to physically travel across oceans.

This architecture solves that by completely decoupling the storage (S3) from the delivery (CloudFront). The website is cached at hundreds of edge locations globally, meaning a user in Tokyo downloads the site from a Tokyo server, while a user in New York downloads it from New York. It is instantly scalable, highly secure, and extremely cost-efficient.

Architecture Data Flow
1
DNS Resolution (Amazon Route 53)
When a user types tjbest.dev, Route 53 acts as the highly available DNS service. An Alias (A) record instantly routes the user's request to the nearest CloudFront edge location.
2
Edge Delivery (Amazon CloudFront)
CloudFront receives the request. If the website assets (HTML, CSS, JS, images) are already cached at this local edge node, it serves them instantly (<50ms). If not, it requests them from the S3 origin. CloudFront is also configured to forcefully redirect all HTTP traffic to secure HTTPS.
3
SSL/TLS Security (AWS Certificate Manager)
ACM provides the public SSL certificate that validates the identity of the website and encrypts all transit data. The certificate is attached directly to the CloudFront distribution and covers both the root domain and wildcard subdomains.
4
Origin Storage (Amazon S3)
An S3 bucket serves as the highly durable (11 9s) origin storage for the raw code files. It is configured for static website hosting, but bucket policies can be tightened to only allow access from the CloudFront distribution (OAC) to prevent direct public access bypass.
